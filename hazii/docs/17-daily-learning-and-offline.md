# Ежедневное обучение и офлайн-курсы

Дата: 10 октября 2026. Изменения в существующем React/Vite-приложении Sino.
База PostgreSQL и ранее созданные карточки сохранены. Новых миграций нет.

## Что работает

- Главная для выбранного профиля — «Сегодня»: очередь повторений HSK/своих
  тематических курсов, короткое занятие из пяти новых слов, переход к трудным
  словам и чтению. Гость видит прежнее приветствие и каталог HSK.
- Навигация: нижняя панель на телефоне и левая колонка на компьютере.
  В упражнениях панель скрыта; есть выход обратно в курс. Выход из профиля
  доступен на телефоне в самом профиле.
- Четыре отдельных показателя: узнавание, ввод слова, понимание на слух,
  письмо. Старые общие отметки «Знаю» не превращаются в четыре навыка.
- «Мои трудности» сохраняет неуспешные проверки с пояснением. Повторение
  запускается по конкретному слову и навыку, а не со случайной позиции курса.
  Успешная повторная попытка закрывает трудность, но не переписывает
  статистику первых попыток.
- В статье БКРС можно выбрать существующую тему или создать новую,
  вписать краткое значение и сохранить карточку. Предложение из режима
  чтения переносится в заметку. Полная статья не копируется целиком в карточку.
- Три собственных коротких текста: «Знакомство», «Чашка чая», «Планы на
  выходные». Разбор слов, статьи БКРС и сохранение контекста используют
  существующий словарь. Уровни текстов редакционные, не сертификация HSK.
- Аудирование использует китайский голос устройства. До успешного
  воспроизведения проверить ответ нельзя. Нет подходящего голоса — есть
  понятное сообщение, без подмены озвучкой на другом языке. Это синтез речи,
  а не запись диктора; доступность и произношение зависят от устройства.
- Основные настройки перед занятием — режим и число слов. Остальные
  собраны в «Дополнительно». Советы панды: автоматически, после занятия,
  по нажатию либо полностью скрыть.

## Где находятся данные

HSK-прогресс, дневник, навыки и настройки остаются в localStorage, отдельно
для каждого локального профиля. `learningInsights.js` отвечает за навыки
и трудности; `studyStorage.js` фиксирует проверку; `courseManagement.js`
сбрасывает данные только выбранного курса. Выход не удаляет записи.

Свои карточки, папки и их статистика находятся в PostgreSQL. Доступ по
случайному ключу коллекции из браузера. Это не полноценная авторизация:
имя/email локального профиля не подтверждают личность; очистка браузера
может лишить доступа к ключу. Пароль, OAuth, восстановление доступа,
синхронизация HSK между устройствами пока не реализованы.

ANKI — самооценка узнавания, не независимая проверка знания. В счётчиках
навыков учитывается последняя успешность по словам; эти числа не являются
оценкой владения языком или готовности к экзамену.

## Офлайн

В собранной версии в каждом HSK есть «Курс с собой». Скачиваются оболочка,
шрифты, каталог выбранного курса и данные его уникальных иероглифов.
Показываются объём, ход скачивания и кнопка удаления. Для HSK 1 в проверенной
сборке получилось около 5 МиБ; объём зависит от сборки. На Vite dev загрузка явно отключена.

- `scripts/offlineManifest.mjs` формирует список публичных файлов сборки.
- `features/offline/offlineCourses.js` загружает максимум четыре файла
  одновременно в отдельный CacheStorage-пакет. Маркер готовности пишется
  последним. Незавершённая загрузка не подменяет предыдущую готовую копию.
- `public/sw.js` открывает завершённый пакет при отсутствии сети. Из API
  разрешено брать из этого кэша только публичные данные `/api/hanzi/...`.
  Личные ответы API, токены и статьи словаря в общий кэш не записываются.
- Удаление скачанного курса не меняет личный учебный прогресс. Браузер
  может удалить кэш при нехватке места; это не резервная копия данных.
- Словарь БКРС, личные папки и некоторые голоса требуют интернета.
  Очереди отправки личных ответов на сервер и облачной синхронизации HSK нет.

Ограничения браузерного хранилища: [MDN CacheStorage](https://developer.mozilla.org/en-US/docs/Web/API/CacheStorage)
и [квоты и очистка](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

При проверке production исправлена отдельная ошибка HanziWriter: CSS-сборщик
сжимал rgba-цвет в восьмизначный HEX, который движок не принимает.
`writingColors.js` переводит цвет обратно на границе библиотеки.

## Проверки

- `npm run lint`, `npm run build`.
- 49 тестов, включая PostgreSQL и БКРС, с флагами
  `PERSONAL_CARDS_DB_TESTS=1`, `DICTIONARY_DB_TESTS=1`; без пропусков.
- `scripts/checkResponsive.mjs`: 180 сочетаний экранов/ширин/тем,
  диалоги в портретном и альбомном режиме, типографика.
- `scripts/checkPersonalFoldersUi.mjs`: создание, обучение, перенос,
  дневник, снятие курса, 18 заполненных экранов, увеличенный текст.
- `scripts/checkLearningJourney.mjs`: текст → БКРС → карточка с контекстом →
  тематический курс; ошибка → трудность → повторение; недоступный голос;
  мобильный выход и возврат; 25 заполненных экранов.
- `scripts/checkOfflineCourse.mjs`: отдельный production preview, чистый
  контекст браузера, отключённая сеть и удалённый случайный shell-кэш;
  холодное открытие, карточки, перевод, данные прописей и сохранность
  прогресса после удаления загрузки.

Браузерные проверки — Chromium/Edge, не реальные Safari/iPhone/Android.
Реальная озвучка и рисование пальцем требуют проверки на устройствах.
Тесты создают собственные временные аккаунты и удаляют только их.

## Публикация — ещё не выполнена

Пользователь попросил временное размещение последним этапом. Запрошен выбор:
существующий VPS/хостинг, помощь в его выборе или временная защищённая ссылка
с работающего компьютера. Ответ ещё не получен. Публичного URL этой версии нет.

Загрузка только `dist` не переносит Express API/PostgreSQL/Redis и оставит
словарь и личные папки неработающими. Sites без переработки текущего backend
не является полноценной заменой этого сервера. Нужны выбранная площадка,
доступ владельца и согласованные условия; платные ресурсы не создавались.

Для временного интернет-теста: собранный frontend и API под одним origin,
HTTPS, ограничение доступа к тестовой версии; не открывать наружу Vite dev,
порты БД, Redis, файлы проекта или существующие локальные пользовательские
данные. Для постоянного публичного запуска сначала необходимы защищённые
аккаунты, восстановление, серверная синхронизация и резервное копирование.
