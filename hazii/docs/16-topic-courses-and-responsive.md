# Тематические курсы и адаптивный интерфейс

Обновлено: 10 октября 2026.

## Как пользоваться

1. Откройте «Свои карточки» под своим локальным профилем.
2. Нажмите «Создать папку», укажите конкретную тему: например, «Путешествия».
3. Создайте карточки в этой папке. Тема для новой карточки обязательна.
4. Нажмите «Учить тему»: можно выбрать направление перевода, количество и
   фильтр слов, включая карточки, срок повторения которых уже наступил.
5. Нажмите «Взять как курс». В профиле появится отдельный тематический курс
   со шкалами и кнопкой продолжения занятий.

Название темы можно изменить. Выбранные слова можно массово переместить
в другую папку — их результаты и срок повторения не обнуляются.
Прежние карточки без папки сохранены и доступны через фильтр «Без темы».
Удаление курса из профиля требует подтверждения и снимает только запись
на курс: папка, карточки и история остаются.

Одно слово в личной коллекции соответствует одной карточке и одной папке.
Дублирование одного слова по нескольким темам пока не поддерживается:
существующую карточку нужно переместить. Вся коллекция по-прежнему доступна
через «Все темы». Максимум: 100 папок и 2000 карточек на владельца.

## Что означает статистика

- Всего слов — текущий состав папки.
- Изучено — последний ответ отмечен «Помню» или «Легко».
- На изучении — всего минус изученные; «Ещё учу» возвращает слово сюда.
- Пора повторить — слова с наступившим сроком повторения.
- Иероглифы в изученных словах — уникальные китайские знаки в таких словах.
  Этот показатель не утверждает, что пользователь научился их писать.
- Успешные самооценки — успешные ответы / все ответы, а не доля уникальных слов.
- Дневник темы — слова по дате первого успешного повторения, в часовом поясе
  браузера. Повторный успех не создаёт вторую запись первого изучения.

При переносе слова показатели обеих папок пересчитываются по их текущему
составу. Дата первого успеха переносится вместе со словом. Дневник темы
пока отдельный от календаря HSK. Занятия своей коллекции — переворачиваемые
карточки с самооценкой и расписанием повторений; ввод перевода и прописи
в этой итерации не добавлены к личным темам.

## Устройство кода и БД

- `infra/postgres/init/05-personal-folders.sql` — добавочная повторяемая миграция.
  `personal.folders` хранит владельца, тему, дату создания и `enrolled_at`.
  `personal.cards.folder_id` связывает слова с темой; составной внешний ключ
  `(folder_id, owner_id)` не допускает привязку к чужой папке.
  `personal.card_progress.first_learned_at` хранит первый успешный ответ.
- `api/personalFolders.mjs` — проверка названий, создание, переименование,
  запись на курс, перенос слов и вычисление статистики. Все запросы используют
  владельца, установленного серверной проверкой ключа коллекции.
- `src/features/personal/personalCardsApi.js` — HTTP-запросы и событие изменения
  коллекции. `usePersonalFolders.js` загружает данные и отбрасывает устаревшие ответы.
- `PersonalFolders.jsx` — выбор/создание/переименование тем.
  `MyCardsPage.jsx` — выбор папки для карточки, перенос и тематическое занятие.
- `PersonalFolderCourses.jsx` — курсы профиля, шкалы, дневник и подтверждение
  снятия курса с профиля.

API под `/api/personal`: `GET/POST /folders`, `PATCH /folders/:id`,
`PUT /folders/:id/enrollment`, `POST /folders/:id/move-cards`.
Перенос транзакционный: если хотя бы один ID недоступен владельцу,
не переносится ни одна карточка. Повторная отправка оценки с тем же
идентификатором не увеличивает число ответов.

Миграция не удаляет прежние слова. Для старых карточек дата первого успеха
восстанавливается только из имеющихся квитанций ответов, а не придумывается
по времени установки обновления. На этом компьютере миграция применена.
На другой существующей базе после миграции личных карточек выполните:

```powershell
npm run db:migrate:folders
```

Профили всё ещё локальные, это не полноценная регистрация. Серверные данные
доступны по секретному ключу, сохранённому в браузере. После очистки данных
сайта доступ нельзя восстановить одним вводом email. Защищённый вход,
восстановление и синхронизация устройств — отдельный незавершённый этап.

## Переносы и размеры экрана

`src/components/typography.js` и `ReadableText.jsx` изменяют только отображение,
не исходные статьи БКРС, пользовательский ввод или данные в БД:

- отключены автоматические переносы по слогам и разрывы русских слов;
- внутри слов дефис отображается неразрывным;
- тире между словами связывается с обоими соседями неразрывными пробелами
  и WORD JOINER, чтобы не оказаться первым или последним знаком строки;
- короткие русские предлоги/союзы связываются со следующим словом;
- числа связываются с поддерживаемыми единицами (км, кг, мин, ч, %, ₽, °C);
- китайские слова выделяются локальным `Intl.Segmenter` и не разрываются
  внутри слова; это словарная сегментация браузера, не контекстный перевод;
- авторские абзацы сохраняются. Тире в начале авторского абзаца/списка
  не удаляется и не переосмысляется.

Невозможно одновременно сохранить произвольно длинное слово целым и
уместить его в любое узкое поле. Для таких исключений предусмотрена локальная
горизонтальная прокрутка текста, а не разрыв букв и не растягивание страницы.
Длинные слова не уменьшаются до нечитаемого размера.

`src/responsive.css` подключён после остальных стилей. В нём — гибкие сетки,
узкие экраны, длинный текст, поля ввода, безопасные области экрана и размеры
окон с `dvh`. На телефоне сетки становятся одноколоночными, кнопки переносятся,
поля ввода имеют не менее 16 px. Уменьшение анимации в настройках ОС учитывается.
Анимация страницы больше не сохраняет свой слой после завершения и не
помещает модальные окна под глобальную кнопку темы.

## Проверка

`npm run lint`, `npm run build` и 45 тестов с обоими флагами БД проходят:

```powershell
$env:PERSONAL_CARDS_DB_TESTS = '1'
$env:DICTIONARY_DB_TESTS = '1'
npm test
Remove-Item Env:PERSONAL_CARDS_DB_TESTS
Remove-Item Env:DICTIONARY_DB_TESTS
```

Браузерные сценарии в `scripts/checkResponsive.mjs` и
`scripts/checkPersonalFoldersUi.mjs` используют Playwright и установленный Edge.
Перед запуском сайта и API задайте `SINO_PLAYWRIGHT_MODULE` как абсолютный путь
к `playwright/index.mjs` установленного тестового окружения. Скрипты не скачивают
браузеры. Первый проверяет 180 сочетаний страницы/ширины/темы; второй — создание
папок и карточек, обучение, дневник, перенос результатов, снятие курса, 18 экранов
с заполненными данными, альбомное окно и увеличенный текст. Профиль теста
изолирован; удаляется только созданная этим тестом серверная коллекция.

Ширины: 320, 360, 375, 390, 414, 430, 768, 1024, 1440 CSS px.
Снимки хранятся локально в `tmp/responsive/`. Это проверки движка Chromium,
не результат испытаний на физических iPhone/Android или в Safari.
Перед релизом остаются реальные устройства: клавиатура, вырезы экрана,
масштабирование текста, сенсорные прописи и запуск с домашнего экрана.
