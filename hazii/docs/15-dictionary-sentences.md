# Словарь: разбор предложений

## Как пользоваться

В словаре выберите «Предложение», вставьте китайский текст и нажмите
«Разобрать предложение». Можно начать с кнопки «Попробовать пример».
Нажатие на слово открывает полную статью БКРС с пиньинем, значениями и
примерами, которые есть в исходной статье. В окне — переходы к предыдущему
и следующему слову. Повторяющиеся слова остаются на своих местах.

Пунктиром помечаются слова/знаки без точной статьи. Для них выводится
сообщение об отсутствии данных, а не придуманное значение. Пробелы,
пунктуация, переносы строк, числа и латинский текст сохраняются. Интерактивные
плитки сейчас создаются только для китайских слов. Обычный поиск китайских
и русских слов, а также пиньиня остаётся в режиме «Слово».

## Что означает автоматический разбор

Это лексическая сегментация, не нейросетевой перевод и не определение
единственного правильного значения по контексту. Используется серверный
[Intl.Segmenter](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter)
с китайской локалью и границами слов (ICU в Node.js). Если выделенная группа
есть в БКРС, она сохраняется. Иначе проверяются её подстроки длиной до 12
иероглифов. Динамическое программирование выбирает разбиение с наименьшим
числом неизвестных знаков, затем — с наименьшим числом слов.

Разные группы ICU не склеиваются в длинные словарные выражения. Поэтому
имена, редкие термины, идиомы и неоднозначные предложения могут потребовать
уточнения обычным поиском. Пиньинь и значения берутся из статьи; произношение
многозначных знаков по контексту не выбирается. Традиционные формы ищутся
как написаны, без автоматической конвертации в упрощённые.

## Файлы и API

- `api/dictionarySegmentation.mjs` — сегментация, подбор слов, отдельный router.
- `POST /api/dictionary/segment`, JSON `{ "text": "我喜欢学习中文。" }`.
  Ответ — `tokens` с текстом, UTF-16-смещениями `start`/`end`, `kind`,
  `entryId` (либо `null`) и `pinyin`.
- `DictionarySentenceReader.jsx` — поле предложения, состояния загрузки,
  выбор слова, отмена устаревшего запроса при редактировании или уходе.
- `DictionaryPage.jsx` — режимы поиска, существующее окно полной статьи,
  последовательная навигация, фокус клавиатуры и закрытие через Escape.
- `dictionaryApi.js` — единые относительные `/api/dictionary` URL, без
  обращения к `127.0.0.1` телефона. В разработке работает прокси Vite.

## Нагрузка и данные

Максимум 1000 UTF-16-единиц на предложение, JSON-тело до 8 КБ. Повторные
кандидаты удаляются. Все кандидаты проверяются одним параметризованным
SQL-запросом по существующему B-tree индексу направления/слова. Полные статьи
не отправляются с разбором: их открывает прежний `/entries/:id` по требованию.
Миграция базы данных не нужна; таблицы словаря не изменяются.

Предложение отправляется только серверу Sino методом POST, не попадает в URL,
не записывается в БД и не сохраняется в общем Redis-кэше. Ответ: `no-store`.
Никакие тексты не передаются внешнему сервису ИИ. Для production по-прежнему
нужны ограничения запросов на шлюзе и нагрузочные тесты; этот функционал
сам по себе не подтверждает поддержку тысяч одновременных посетителей.

## Проверки

`npm test` проверяет сегментацию, повторения, Unicode, отсутствие подмены
исходного текста, неизвестные слова, лимиты, ошибки и разметку интерфейса.
Для read-only проверки на реальном БКРС:

```powershell
$env:DICTIONARY_DB_TESTS = '1'
npm test
Remove-Item Env:DICTIONARY_DB_TESTS
```

Проверка через браузер в текущей среде не состоялась: средство управления
браузером завершает процесс с `trusted Node process exited unexpectedly`.
Проверки SSR/API не заменяют визуальный тест на iPhone/Android.
